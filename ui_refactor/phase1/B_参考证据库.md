## 1. The Last of Us Part II

### 1.1 瞄准 HUD（HUD Aiming Crosshair）

**玩家任务**：在昏暗室内持枪瞄准，确认目标与剩余弹药。

**直接可见**：
- 屏幕几乎没有任何常驻 HUD。
- 瞄准时只有中心一个极小的点状准星。
- 右下角有一个很小的弹药指示，低亮度、低对比，不抢画面。
- 武器和角色占据画面主体。

**信息分类**：
- 持续可见：极少的弹药信息。
- 按需出现：瞄准准星。
- 模态：无。

**焦点/动效**：焦点是空间目标本身；静帧无法判断准星扩散/收缩的时长。

**可借鉴**：
- 战斗画面主体优先，常驻信息应“少而准”。
- 弹药只在需要时提高存在感，而不是永久用大数字占据右下角。
- 准星应随武器状态变化，但必须保证在明亮场景可读。

**不应借鉴**：
- 不能把准星和弹药做得同样小；本项目 1280×720 基准、中文 UI，过小会不可读。
- 不复制其具体准星形状、弹药图标或字体。

### 1.2 暂停菜单（Pause Menu）

**玩家任务**：中断游戏，选择继续、设置、保存、退出。

**直接可见**：
- 游戏场景仍在背景中，只是整体压暗；没有大块不透明面板。
- 选项是左对齐的单列文本，全部大写/小字号。
- 当前项更亮，左侧有一个小型标记；其余项更暗。
- 左下/右下是返回/选择提示；大量负空间。

**信息分类**：
- 持续可见：场景上下文（我在哪里暂停）。
- 按需出现：选项列表。
- 模态：是，但视觉上不切断场景。

**焦点/动效**：焦点通过亮度 + 前置标记表达，不依赖彩色边框；静帧无法判断切换动效。

**可借鉴**：
- 暂停应保留“我还在游戏里”的空间上下文，而不是用一张完全遮住场景的大卡片。
- 焦点必须同时有形状/位置线索，不能只靠颜色。
- 选项数量少时，留白比堆说明更高级。

**不应借鉴**：
- 不复制其左列布局、全大写英文、字号或标记符号。
- 本项目联机暂停不能让玩家误以为服务器停了；必须明确“战斗继续”，并给出实时生命/队伍状态。

### 1.3 场景内提示（Gameplay Hints）

**玩家任务**：在探索中拾取物品、学习补给品用途。

**直接可见**：
- 左上角一个“物品 + 按键”提示，文字很短。
- 左侧中部一个教学提示，图标 + 两行短句。
- 没有常驻的底部操作长条。
- 提示贴近其指向的物体/区域，不遮住准星。

**信息分类**：
- 持续可见：无。
- 按需出现：靠近可交互物/首次遇到系统时。
- 模态：无。

**焦点/动效**：提示本身是焦点；静帧无法判断淡入淡出。

**可借鉴**：
- 交互提示应“靠近才出现、离开就消失”，并和具体对象绑定。
- 图标 + 动词 + 按键的结构比一整行键位表更容易扫读。
- 同屏最多保留一个主要交互提示。

**不应借鉴**：
- 不复制图标风格、字体或位置。
- 本项目已有世界内 Label3D，不能既保留世界标签又在 HUD 重复同一句话；应选一个主提示源。

### 1.4 武器切换（Weapon Switcher）

**玩家任务**：在战斗中快速切换武器，确认每把武器的弹药。

**直接可见**：
- 按住/触发后出现一组武器条目，每项有武器轮廓图标、弹药数字/弹匣图示。
- 背景场景仍然可见，切换层不铺满全屏。
- 右下有“SWAP WEAPON”操作提示。
- 条目沿屏幕右侧纵向排列，中心视野不被完全遮挡。

**信息分类**：
- 持续可见：当前武器的小弹药。
- 按需出现：武器列表与每把武器弹药。
- 模态：准模态，短暂拦截输入。

**焦点/动效**：当前武器有高亮；静帧无法判断切换动画。

**可借鉴**：
- 武器/弹药是“按需展开”的信息，不需要永久占据右下角两块面板。
- 每项应同时显示“武器身份 + 剩余弹药”，而不是只显示名字。
- 展开层应避开准星与主要威胁方向。

**不应借鉴**：
- 不复制其图标、径向/纵向布局或配色。
- 本项目只有两把出战武器，不需要复杂的武器轮盘；两槽切换应更快、更安静。

### 1.5 技能升级（Skill Upgrades）

**玩家任务**：在安全点选择要解锁的技能。

**直接可见**：
- 右侧一个半透明深色面板，场景仍可见。
- 顶部是技能树/分类图标，当前分类高亮。
- 左侧是纵向技能节点，当前节点有明亮描边和图标；右侧是标题、说明、数值增益。
- 底部是“学习/返回”按键提示。
- 文本层级清楚：分类 > 技能名 > 说明 > 数值。

**信息分类**：
- 持续可见：当前分类与技能树位置。
- 按需出现：选中技能的说明。
- 模态：是，但保留场景。

**焦点/动效**：选中节点用描边 + 亮度 + 图标共同表达；静帧无法判断悬停/按下的缓动。

**可借鉴**：
- 抽卡/强化选择应有明确的“当前焦点/已选/不可选”三态，且不仅靠颜色。
- 说明文字应短，数值增益单独成行。
- 面板不应铺满全屏；保留战斗场景上下文。

**不应借鉴**：
- 不复制其科幻边框、图标体系、节点形状。
- 本项目抽卡是 3 选 1 的即时决策，不能做成需要阅读长文的技能树。

### 1.6 地图（Map）

**玩家任务**：在探索中确认位置与路线。

**直接可见**：
- 地图是角色双手举起的实体纸张，占据大部分画面，但是“世界内物件”，不是屏幕 UI。
- 地图上有手写标记、路线、图例；没有常驻小地图叠加。
- 右下有翻面提示。

**信息分类**：
- 持续可见：无。
- 按需出现：打开地图时。
- 模态：是，暂时遮挡视野。

**可借鉴**：
- 地图应是“主动查看”的模式，而不是永久占用右上角。
- 地图信息应有明确的视觉层级（区域 > 路线 > 标记）。
- 可以让地图/战术信息与世界观发生关系，而不是纯科技面板。

**不应借鉴**：
- 不能把纸质地图直接搬进多人射击：它会遮挡视野、阅读慢、无法快速定位队友。
- 不复制其纸张材质、手写字体或图例。

## 2. Detroit: Become Human

### 2.1 命中标记（Hit Marks）

**玩家任务**：分析伤口/命中部位，获得线索。

**直接可见**：
- 伤口处出现世界锚定的 AR 扫描框，细虚线、角标。
- 标题 `HIT MARKS`，下方两行说明，再下方 `3/5 CLUES TO ANALYZE` 与橙色进度条。
- 信息贴近被分析对象，不在屏幕中央铺开。
- 画面仍有大量场景细节。

**信息分类**：
- 持续可见：扫描框与进度。
- 按需出现：标题/说明在扫描时出现。
- 模态：局部模态。

**焦点/动效**：焦点是被扫描的伤口；静帧无法判断扫描线/进度动画。

**可借鉴**：
- 命中反馈可以空间化、短句化，并与对象绑定。
- 进度/层数用一条细进度条表达，比堆数字更直观。
- 标题、说明、进度三级层次清楚。

**不应借鉴**：
- 不复制其 AR 虚线框、蓝色科技线、字体。
- 快节奏射击中不能要求玩家读两行说明；命中标记应在 0.2–0.4s 内完成表达。

### 2.2 目标提示（Objectives）

**玩家任务**：在场景中确认当前调查目标。

**直接可见**：
- 世界空间中的一块悬浮目标板，顶部一条亮色标题栏，下面 3 行目标。
- 目标板很小，位于场景中，不占满屏幕。
- 没有同时在 HUD 再复制一份目标列表。

**信息分类**：
- 持续可见：当前目标（世界锚定）。
- 按需出现：靠近/查看时。
- 模态：无。

**焦点/动效**：目标板本身就是焦点；静帧无法判断出现/消失方式。

**可借鉴**：
- **单一信息源**：世界锚定与 HUD 只能选一个主展示，不能重复。
- 目标要短，最多 3 条；当前目标优先。
- 世界锚定适合“空间位置重要”的信息，不适合需要精确数值的信息。

**不应借鉴**：
- 不复制悬浮板造型、亮色标题栏、字体。
- 本项目任务核心是“核心数量/交付点/出口”，这些需要稳定可读，不能只靠世界内小字。

### 2.3 主菜单（Main Menu）

**玩家任务**：从主菜单进入继续/新故事/章节/设置/额外内容。

**直接可见**：
- 全屏人物近景，画面本身就是菜单背景。
- 菜单是画面下方一条很薄的横向文字条：`CONTINUE / NEW STORY / CHAPTERS / OPTIONS / EXTRAS`。
- 当前项用左右括号/下划线标记，其他项低亮度。
- 没有大块面板、没有卡片、没有堆叠说明。

**信息分类**：
- 持续可见：品牌/情绪画面。
- 按需出现：菜单项。
- 模态：是，但视觉极轻。

**焦点/动效**：焦点通过括号/亮度和位置表达；静帧无法判断切页动效。

**可借鉴**：
- 主菜单可以让“场景/品牌画面”成为主体，UI 退到边缘。
- 焦点应是一个明确的形状变化，而不是只换颜色。
- 菜单项少而清楚，说明放到次级层。

**不应借鉴**：
- 不复制人物特写、排版、括号符号、品牌语气。
- 本项目主菜单需要 IP/端口/种子等表单，不能照搬“五个词”的极简结构；应在保留功能的前提下减少面板重量。

### 2.4 倒计时（Timer）

**玩家任务**：在时间压力下赶到车站。

**直接可见**：
- 左上角大号 `-00:19:58`，下方一行 `LAST BUS DEPARTS`。
- 倒计时只在有时间压力的任务中出现，不是永久 HUD。
- 数字是画面中最亮的元素之一，背景场景仍可见。

**信息分类**：
- 持续可见：只在限时任务中。
- 按需出现：进入限时区域/事件。
- 模态：无。

**焦点/动效**：数字本身是焦点；静帧无法判断秒数变化/告警动画。

**可借鉴**：
- 紧急信息只在紧急时出现；出现时用大数字 + 短标签，不解释。
- 紧急信息应远离准星和交互提示，避免叠加。

**不应借鉴**：
- 不复制其斜切边框、字体、负号格式。
- 本项目波次/任务没有全局倒计时，不应为了“氛围”增加常驻计时器。

### 2.5 章节选择（Chapters）

**玩家任务**：回顾/重玩章节，理解叙事分支。

**直接可见**：
- 白色/浅色全屏背景，章节以倾斜卡片/缩略图沿对角线排列。
- 当前章节用蓝色条和标题标记，其他章节低亮度。
- 底部是 `LAUNCH CHAPTER / FLOWCHART / BACK` 操作提示。
- 信息层级：章节标题 > 缩略图 > 操作。

**信息分类**：
- 持续可见：章节结构。
- 按需出现：当前章节详情。
- 模态：是。

**焦点/动效**：焦点通过色块、位置和缩略图表达；静帧无法判断转场。

**可借鉴**：
- 局外档案/历史行动可以用“空间化历史”表达，而不是一串文本。
- 当前项要有明确的色块/位置焦点。

**不应借鉴**：
- 不复制其浅色背景、倾斜卡片、蓝色条。
- 这不是战斗 HUD 的参考；本阶段试点不扩展到章节/档案重做。

## 4. 横向结论

### 4.1 可迁移的原则

1. **常驻信息极少，按需信息丰富**：瞄准、交互、切枪、限时、目标详情都在需要时出现；常驻只保留生命/弹药/队伍等生存必需。
2. **一个信息只有一个主来源**：世界锚定或 HUD，二选一；不能像当前工程那样两处重复。
3. **焦点是形状 + 位置 + 亮度**：不能只换颜色，更不能 `StyleBoxEmpty`。
4. **场景是主体**：暂停/升级/菜单都保留场景上下文；覆盖层不无故铺满全屏。
5. **短句 + 三级层次**：标题 > 关键数值 > 一句说明；不用一段话解释操作。
6. **紧急信息用大数字 + 短标签**；非紧急信息退到边缘或隐藏。
7. **动效服务于状态变化**：淡入/位移/进度必须能被打断，不能延迟输入；静帧不能证明时长，需实机录像验证。

### 4.2 明确不借鉴

- 不复制任何具体布局（左列暂停、对角章节卡、右侧技能树、径向武器盘）。
- 不复制图标、字体、配色、边框、品牌符号、角色画面。
- 不把“科幻 AR/全息板”当作本项目的默认视觉语言；本项目的视觉基础是低多边形末日城市。
- 不为“沉浸感”增加常驻装饰、扫描线、噪点或大面积玻璃面板。
- 不把静帧观察当成动效验证；不在没有录像的情况下写具体时长/缓动。
