# C · 阶段一诊断与优先试点方案

> 本文件是阶段一的交付结论。它不修改代码，只回答五个问题：**保留什么、重做什么、只调什么、拆什么、还缺什么证据**；然后给出有优先级的试点顺序。
> 事实与证据编号见 [A_工程证据与架构审计.md](A_工程证据与架构审计.md)，参考原则见 [B_参考证据库.md](B_参考证据库.md)。

## 1. 诊断结论

现有 UI 的视觉方向是成立的：深青绿 + 琥珀 + 危险红、低多边形末日夜景、克制的标题字，已经形成可识别的气质。真正的问题在**结构**：

1. **布局是“像素坐标 + 固定矩形”，但内容是变化的**。4 人队伍、不同任务文案、不同武器数量都会改变最小尺寸；`PanelContainer` 会撑开，固定矩形不会。结果不是“稍微挤”，而是第 4 名队员被任务面板盖住、生命面板在所有分辨率越出底边。
2. **主菜单没有纵向预算**。16:9 下最小高度 741 > 720，右侧简报底部被裁切；21:9 同样；只有 16:10 能放下。没有滚动容器，也没有“次要信息折叠”。
3. **输入与焦点不是系统，而是补丁**。移动/射击/UI 全是硬编码键鼠；没有 InputMap/手柄；Theme 的 focus 是空的；抽卡/军械库/背包卡片根本无法获得焦点。
4. **信息优先级没有分层**。底部操作长条、世界 Label3D、HUD 交互提示、任务面板说明同时存在；搬运核心时弹药面板仍说“就绪”；加载条是假的 64%。
5. **表现与业务耦合在三个大脚本**。不是“文件多”，而是**没有视觉层**：没有 Theme 资源、没有 UI 场景、没有组件；每次改动都要改代码，无法截图对比，也无法给设计/测试一个稳定接口。

一句话：**先修信息架构和布局系统，再谈质感；先让状态真实、焦点可见、信息不重叠，再谈动效和装饰。**

## 2. 保留

以下内容不建议推翻，试点应保持其接口与数据语义：

| 保留项 | 原因 |
|---|---|
| 深青绿/琥珀/危险红的色彩方向 | 与低多边形夜景一致；问题在用法（红色滥用、对比不足），不是色相本身 |
| 主菜单的信息架构：部署终端 + 行动简报 + 局外档案 + 军械库 + 退出 | 功能完整，符合“创建/加入/单人/局外成长”的任务流；只需重排纵向预算与层级 |
| 大厅的 4 槽位、房主开始、准备状态、局外档案 | 与网络权威模型一致；保留 `show_lobby/update_lobby` 接口 |
| HUD 的 10 类信息与数据源 | 分类本身合理（队伍、任务、波次、地图、生命、弹药、武器、交互、击杀、横幅）；保留 `set_*` 数据入口 |
| 暂停语义：单人暂停、联机继续服务器模拟 | 符合任务要求；需要补的是“联机暂停仍可能受伤”的反馈，而不是改回暂停服务器 |
| 现有信号契约与网络协议 | 避免破坏联机、存档、任务；试点通过 facade 内部替换视图 |
| 现有可用功能与旧回退路径 | 试点期间保留旧 `MainMenu/GameHUD` 可切换，验收后再决定是否移除 |

## 3. 重新设计

### 3.1 战斗 HUD 的空间与信息架构（P0）

不是“换皮”，而是重新定义**安全区 + 信息分区 + 内容驱动尺寸**：

- 左上：队伍（4 人必须完整可见；1 人时不留 164px 空洞，采用紧凑行或 2×2）。
- 左中：任务（核心数、交付点、搬运状态、下一目标）；与队伍面板之间用**计算出的间距**，不再固定 y=190。
- 上中：波次/威胁（保留，但降低常驻高度；非战斗阶段可收起）。
- 右上：地图（缩小、降低红框；队友/威胁图例与 HUD 统一）。
- 左下：生命（底部锚定，尺寸由内容决定；低血量状态与数字同层）。
- 右下：武器/弹药（合并为一个“当前武器”块；搬运核心时显示禁用态与原因）。
- 下中：交互提示（单一来源；与世界 Label3D 二选一）。
- 底部常驻键位长条：**删除常驻**，改为首次教学/按住帮助/暂停内键位表。
- 覆盖层：情报/背包/抽卡/暂停/结束共用统一的 `OverlayShell`（遮罩、焦点陷阱、返回、层级）。

验收的硬指标：1280×720、1920×1080、1920×1200、2560×1080 下**零面板重叠、零越界、4 人队伍完整可见**。

### 3.2 主菜单的纵向预算（P0）

- 右栏“行动简报”改为**可滚动/可折叠**：4 条说明 + 颜色图例 + 操作 + 提示，按优先级显示；底部提示不参与首屏高度竞争。
- 左栏表单与档案保持，但把“退出”从内容流底部移到固定角落/次级区，避免被内容挤出。
- 1280×720 下首屏必须能看到：创建/加入/单人、呼号/种子/IP/端口、军械库、退出；简报至少看到 4 条标题，详情可滚动。
- 不做“全屏视频背景/角色特写”之类需要新美术资产的方案；先在现有低多边形夜景上减面板、加留白。

### 3.3 大厅状态表达（P1）

- 空槽与“全员已准备”不能同时出现；文案按 `已连接人数` 与 `all_ready` 组合：
  - 1/4 且房主已准备：`等待队员加入 · 当前 1/4`，开始按钮可用但明确“可单人开始/等待队友”。
  - 2–4/4 未全准备：`还有 N 人未准备`。
  - 全准备：`全员已准备 · 房主可开始`。
- 客户端准备增加 `准备中…` pending 态，收到服务器广播后再落定；失败/超时给出可行动的错误。
- 空槽不再显示“等待队员加入…”与“全员已准备”冲突的组合。

### 3.4 暂停/覆盖层（P1）

- 暂停不再用一张完全遮住场景的 460×320 卡片；改为**保留场景的左侧信息列 + 右侧实时队伍/生命摘要**（不复制 TLOU 布局，只采用“场景仍在”的原则）。
- 联机暂停必须显示：`服务器仍在运行`、本地生命/倒地状态、队友状态；如果玩家在暂停中受到伤害，要有可见反馈。
- 统一 `OverlayShell`：背景遮罩强度、焦点陷阱、Esc/返回、打开时释放鼠标、关闭时恢复鼠标与输入。
- 背包/军械库本阶段**不重做完整信息架构**：只处理打开/关闭、焦点、禁用态、对比度；不扩展为新的背包系统。

### 3.5 抽卡/强化选择（P1，属于 HUD）

- 3 张卡可聚焦（键盘/手柄）、有明确 `focus/selected/disabled` 三态；不再 `FOCUS_NONE`。
- 卡片信息压缩为：标题（大）→ 增益（中）→ 一句说明（小）→ 按键提示；描述在琥珀卡上的对比度必须 ≥4.5:1。
- 抽卡期间保留“角色原地读取核心数据”的世界状态，但不要用全屏不透明遮罩切断场景；遮罩强度与焦点层级统一。

### 3.6 加载与任务结束（P1/P2）

- 加载：如果拿不到真实进度，就用**不确定进度**（循环/脉冲）而不是假的 64%；提供“正在生成街区 #seed”与阶段文案；如果生成不可取消，不要放一个看起来可点的取消。
- 任务结束：保留现有胜负色与统计，但把“返回大厅”作为唯一主操作，次要操作（再来一局/查看档案）按需；避免 600×380 卡片内大片空白。
- 任务结束/加载状态必须能被真实流程捕捉；如果 CLI 抓不到，增加测试钩子或明确标记为未验证。

## 4. 仅样式调整

这些不需要改结构，但必须在试点中一起收敛，否则“结构修好了仍然不好读”：

| 项 | 调整 | 证据 |
|---|---|---|
| 字号/字重/行高 | 关键数值 ≥18px；说明 ≥12px；禁用/次要 ≥12px；建立 4–5 级字号，不再出现 8/9px 承担关键信息 | 审计字号分布：8/9/10/11px 共 30+ 处 |
| 对比度 | 常驻提示删除或改为高对比；禁用态 ≥4.5:1；抽卡描述/琥珀卡 ≥4.5:1；世界标签加描边/底板 | 1.12:1、3.01–3.11:1、4.00:1 |
| 红色语义 | 红色只用于危险/失败/低血量；小地图红框、`LIVE` 红点、`NIGHT 07` 红改为中性/青色 | 截图与 `minimap.gd` |
| 面板材质 | 降低不透明面板数量；统一圆角/边框/内边距；去掉无意义的角标/扫描线 | 现有面板 10+ 块 |
| 武器/弹药 | 合并重复信息；当前武器强调，备用武器降级；空仓/换弹/搬运三态颜色 + 文案 | 截图 |
| 世界标签 | 缩小字号/降低不透明度/拉远距离；交互标签只在准星附近出现 | `mission_site.gd` 26–58px |
| 准星 | 保持白+黑描边，但增加明亮地面下的对比策略；命中标记不只靠颜色 | 截图 |
| 图标 | 如需新增，使用自绘几何/文字符号，不复制参考游戏图标；先做 3–5 个必要的（交互、核心、出口、弹药、危险） | 当前几乎无图标 |

## 5. 需要工程拆分

### 5.1 为什么现在是“大脚本动态构建”

**事实（STATIC_VERIFIED）**：

- 全工程只有 `main.tscn`，没有 UI 场景、没有 Theme 资源。
- `main.gd:_build_ui()` 直接 `MainMenu.new()` / `GameHUD.new()`；两个类的 `_build()` 里分别有 72 / 112 处 `.new()`。
- 列表型 UI（队伍行、武器卡、抽卡、背包）必须在运行时按数据重建，所以天然倾向代码构建。
- 样式通过 97 + 59 处 `add_theme_*` 与 Theme 的 7 处设置；字体每次 `SystemFont.new()`。
- 所有信号在 `main.gd` 集中连接，UI 类不持有网络/玩家节点。

**推断（非事实）**：这是“代码优先”的快速迭代路径：不维护场景与脚本两份结构、不需要美术管线、数据驱动列表直接 `new()`、单语言即可改 UI。它在原型期是合理的；进入商业级迭代后，代价变成：布局不可视化、无法截图回归、无法复用、焦点/状态容易漏、每个改动都要读大脚本。

### 5.2 目标分层（保持接口稳定）

```text
网络 / 玩家 / 任务（权威状态）
        │ 信号、summary、RPC 结果
        ▼
UI 状态适配层（HudState / MenuState，纯数据）
        │ 只做字段映射、优先级、格式化，不碰 Node
        ▼
视图层（Theme 资源 + Control 场景 + 组件）
        │ 只负责布局、绘制、焦点、动效
        ▼
动效控制器（可打断的 Tween/状态机）
```

**稳定边界**：

- 保留 `MainMenu` / `GameHUD` 的公开方法与信号名（`setup_world`、`set_roster`、`set_health`、`set_ammo`、`set_mission`、`set_interaction`、`open_intel`、`open_backpack`、`show_draw`、`show_game_over`、`set_pause_visible` 等）。
- 内部改为 `view.apply(state)`；外部调用方不需要改。
- 把 `main.gd` 的 `hud.call("...")` + `has_method` 改为**类型化方法**；保留旧方法名作为薄封装，避免一次性破坏。
- 网络协议、存档结构、装备数据、任务/战斗规则不改。

**渐进拆分顺序**（避免机械拆成大量小文件）：

1. 新建 `Theme` 资源：颜色/字号/间距/面板/按钮/focus；先让旧 UI 使用它，视觉不变。
2. 抽出 3 个高复用组件：`HudPanel`（标题/内容/尺寸策略）、`StatusRow`（队伍/武器/属性行）、`OverlayShell`（遮罩/焦点/返回）。
3. 只把**主菜单、大厅、战斗 HUD**迁移到组件；背包/军械库仅接样式与焦点，不重做结构。
4. 会话/战斗状态改为 `HudState` 字典，HUD 只读；去掉每帧重建样式与字符串。
5. 最后再处理动效控制器与性能（隐藏菜单停止处理、地图重绘节流、字体缓存）。

**不做什么**：

- 不把所有面板拆成独立脚本；组件按“复用 + 状态边界”拆，不按“一个控件一个文件”。
- 不在本阶段引入第三方 UI 框架；Godot 原生 Theme/Control 足够。
- 不为了“架构漂亮”改动网络/存档/任务状态机。

## 6. 证据不足，暂不做设计结论

| 问题 | 当前证据 | 为什么不能现在定 |
|---|---|---|
| 真实 4 人联机 HUD/大厅 | 注入数据复现布局缺陷；未跑 3 个真实客户端 | 不知道真实网络下队伍行高、名字长度、延迟状态是否还会变化 |
| 联机暂停时是否仍会受伤 | 代码显示服务器继续，玩家输入禁用 | 没有实战验证；如果会受伤，暂停 UI 必须显示实时生命/倒地；如果不会，文案要改 |
| 手柄/Steam Deck 全流程 | 代码层确认无映射 | 不知道目标手柄、死区、辅助瞄准、UI 导航范围；不能凭代码猜手感 |
| 性能 | 静态线索（隐藏菜单仍处理、每帧重绘、字体新建） | 没有 profiler；不能声称“卡”或给出优化收益 |
| 3–5 名测试者可用性 | 未做 | 不能判断玩家是否真的会在战斗中打开背包/看懂搬运状态 |
| TLOU/Detroit 动效时长 | 只有静帧 | 不能编造时间码/缓动；动效需实机录像或自己测试 |
| 1920×1200/超宽真实窗口 | 离屏审计 | 真实窗口受桌面可用高度限制；需要换显示器/无边框方案再验 |
| 加载是否可异步/可取消 | 代码是假进度 | 不知道世界生成是否可分帧；不能承诺真实进度条 |
| 军械库是否扩展更多武器 | 当前 7 把刚好排满 | 未来内容量未知；先做滚动/换行策略，不重做军械库 |

这些项在阶段二/四开始前应逐项补证；补证前只做**不依赖它们**的结构修复（碰撞、越界、焦点、对比度、单一提示源）。

## 7. 优先试点方案

原则：**先修客观缺陷，再修状态表达，最后做视觉/动效**。每个试点都是可回退的小步，不一次性重写 UI。

### P0-1 · UI 基础层与输入可达性

**范围**：Theme 资源、颜色/字号/间距 token、focus 样式、InputMap 动作、HUD 缩放/安全区根节点、类型化 HUD 接口（薄封装）。

**为什么先做**：焦点/输入是阶段五验收的硬门槛；没有它，后面所有视觉工作都无法被键盘/手柄用户使用。

**任务**：

- 建立 `Theme` + `ThemeVariants`；把 `ui_theme.gd` 的散落值收敛；先保持现有视觉不变。
- 为所有可交互控件提供可见 focus（形状 + 亮度 + 位置），取消抽卡/军械库/背包的 `FOCUS_NONE`。
- 增加 `InputMap`：移动/冲刺/跳跃/射击/瞄准/换弹/交互/放下/情报/背包/暂停/UI 导航；保留现有键鼠映射，新增手柄映射。
- 建立 `SafeAreaRoot`：按视口/安全区计算 UI 边距；提供 HUD 缩放 100–150%。
- 把 `main.gd` 的 `hud.call` 改为类型化调用，旧方法保留。

**验收**：

- 仅用键盘可完成：主菜单 → 创建/加入 → 大厅准备/开始 → 战斗 → 开/关情报/背包 → 暂停/返回。
- 仅用手柄可完成同样的 UI 流程（战斗手感调优可另立任务，但 UI 导航必须可用）。
- 每个可聚焦控件都有可见焦点；截图对比可证明。
- 现有键鼠操作无回归。

**回退**：Theme/focus 变更可单独 revert；InputMap 是新增动作，不删除旧物理键路径。

### P0-2 · 布局碰撞与纵向预算

**范围**：主菜单、战斗 HUD（队伍/任务/生命/武器/交互/小地图）。

**任务**：

- 主菜单：右栏简报滚动/折叠；退出固定到角落；1280×720 首屏完整。
- HUD：队伍面板内容驱动（4 人完整、1 人紧凑）；任务面板位置由队伍面板底部计算；生命面板底部锚定并按内容定高；武器/弹药合并或对齐。
- 所有面板加安全区约束；禁止 `PanelContainer` 超出锚点矩形（必要时用 `custom_minimum_size` + 容器，而不是固定 offset）。
- 加自动布局测试：在 4 个分辨率 + 1/2/4 人 + 长文案下检查重叠/越界。

**验收**：

- 4 个目标分辨率 × 1/2/4 人 × 长任务文案：零重叠、零越界、4 人全可见。
- 1280×720 主菜单：创建/加入/单人、四个输入框、军械库、退出、简报 4 条标题全部可见（详情可滚动）。
- 截图 diff 与 JSON 审计都通过；不是肉眼判断。

**回退**：旧 `MainMenu`/`GameHUD` 保留；新布局通过 feature flag 切换，验收后默认新布局。

### P1-1 · 战斗信息优先级与状态真实

**范围**：HUD 常驻信息、交互提示、搬运/空仓/换弹/低血量状态。

**任务**：

- 删除常驻底部键位长条；改为首次教学/暂停键位表/按住帮助。
- 交互提示单一来源：世界 Label3D 与 HUD 二选一（推荐 HUD 主提示 + 世界标签仅在靠近时低透明度显示对象名）。
- 搬运核心：弹药/武器块显示“搬运中 · 无法射击/换弹”，而不是“就绪”；准星/交互状态同步。
- 空仓/换弹/低血量：颜色 + 文案 + 形状三重编码，不仅靠颜色。
- 小地图：去掉红框/红 LIVE 的危险暗示；统一队伍/丧尸/标记色与图例。

**验收**：

- 搬运核心时，玩家不看任务面板也能从武器区知道不能开火。
- 任意时刻同屏只有一个主要交互提示。
- 底部不再有常驻 11px 提示；首次教学可跳过/重看。
- 空仓/换弹/低血量在明亮与昏暗背景下均可读（对比度 ≥4.5:1 或 ≥3:1 大字号）。

### P1-2 · 大厅/暂停/覆盖层状态

**范围**：大厅、暂停、情报/背包打开关闭、任务结束。

**任务**：

- 大厅文案状态机：连接数 × 准备数 × 房主/客户端；pending 准备态；空槽不误导。
- 暂停：保留场景；显示联机服务器仍在运行 + 本地/队友实时状态；焦点陷阱；Esc/返回；鼠标捕获恢复。
- `OverlayShell` 统一遮罩/层级/焦点/关闭行为；打开覆盖层时禁止后台 HUD 抢焦点。
- 任务结束：主操作唯一；统计层级；返回大厅后状态清理。
- 背包/军械库不重做结构，只修焦点/禁用态/对比度。

**验收**：

- 4 人真实/模拟大厅：任何连接/准备组合下文案不矛盾；客户端准备有 pending → confirmed 两态。
- 联机暂停时能看到服务器继续与生命状态；关闭后鼠标/输入恢复。
- 打开/关闭覆盖层不丢失焦点、不重复触发、不暂停服务器。
- 任务结束返回大厅无残留遮罩/输入锁。

### P1-3 · 抽卡/强化选择可达性

**范围**：抽卡 3 张卡、强化说明、确认/放弃。

**任务**：

- 卡片可聚焦，焦点/选中/禁用三态；键盘 1/2/3 与手柄导航都可用。
- 文案压缩；对比度修正（琥珀卡描述/`Lv`）。
- 抽卡打开/关闭动效可打断；不延迟输入。
- 抽卡期间世界状态保持可见（降低遮罩不透明度），但焦点只落在卡片。

**验收**：

- 仅键盘/手柄完成 3 选 1 与放弃；焦点始终可见。
- 3 张卡在 1280×720 不溢出，长中文描述不裁切（或可滚动）。
- 对比度达标；抽卡不阻塞服务器。

### P2-1 · 动效与性能收敛

**范围**：覆盖层过渡、按钮 hover/press、横幅/击杀、菜单背景、小地图、暗角、加载。

**任务**：

- 建立动效 token（时长/缓动/可打断）；覆盖层 120–180ms 淡入/位移，输入不等待动画。
- 减少动效开关：暗角脉冲、背景粒子、非必要过渡可关闭/降低。
- 主菜单隐藏时停止 `MenuBackdrop._process`/重绘；小地图节流/缓存字体；HUD 每帧字符串只在值变化时更新。
- 加载改为真实进度或不确定进度；不显示假 64%。

**验收**：

- 动效不延迟输入；重复按键不叠加/不卡死。
- 减少动效模式下无脉冲/无粒子；功能不受影响。
- profiler 对比有数据（不是“感觉更顺”）；菜单隐藏后无无效重绘。
- 加载状态真实/诚实。

## 8. 试点顺序与依赖

| 顺序 | 试点 | 依赖 | 产出 | 风险 |
|---|---|---|---|---|
| 0 | 补证：真实 4 人联机、手柄、profiler、可用性基线 | 无 | 证据补丁 | 低 |
| 1 | P0-1 基础层与输入 | 0 的手柄结论 | Theme/InputMap/focus/safe area | 中：InputMap 可能影响操作手感，需保留旧键 |
| 2 | P0-2 布局碰撞与纵向预算 | 1 的 SafeArea/Theme | 菜单/HUD 布局修复 | 低：可用旧 UI 回退 |
| 3 | P1-1 信息优先级 | 2 的布局 | HUD 信息分层/状态真实 | 中：会删常驻提示，需要教学补偿 |
| 4 | P1-2 大厅/暂停/覆盖层 | 2 的 OverlayShell | 状态机/暂停/覆盖层 | 中：联机暂停语义需确认 |
| 5 | P1-3 抽卡可达性 | 1 的 focus/InputMap | 3 选 1 可操作 | 低 |
| 6 | P2-1 动效/性能 | 1–5 | 动效 token/性能数据 | 低：可独立回退 |

**为什么不是先做视觉风格**：颜色/字体/面板样式可以在结构稳定后一次性收敛；先做风格会在错误布局上反复返工，也会掩盖碰撞和焦点问题。

## 9. 验收与回退

### 9.1 每个试点的硬验收

- **布局**：4 个分辨率（1280×720、1920×1080、1920×1200、2560×1080）× 1/2/4 人 × 长短文案，自动 JSON 检查零重叠/零越界；截图人工复核。
- **对比度**：文本 ≥4.5:1，大字号/关键图形 ≥3:1；在暗/亮/动态背景上采样；不以“肉眼看着行”代替。
- **输入**：键盘全流程；支持手柄的 UI 全流程；焦点可见；无输入延迟/焦点丢失。
- **联机**：打开 UI 不暂停服务器；准备/开始/抽卡/交付的客户端请求与服务器确认可区分；网络失败有可行动反馈。
- **回归**：18 + 150 逻辑测试全过；新增 UI 布局/焦点测试；真实单人/主机/加入流程通过。
- **可访问性**：HUD 缩放、高对比、减少动效至少各有一个可用开关；参考 Xbox Accessibility Guidelines 逐项记录，不声称“全达标”。
- **性能**：profiler 前后对比；菜单隐藏无无效重绘；地图/字体无每帧新分配。

### 9.2 回退检查点

- 起点标签：`pre-ui-pilot`（`c805ed5`）。
- 每个试点单独分支/提交；禁止把主题、布局、输入、动效混在一个不可拆的提交里。
- 旧 `MainMenu`/`GameHUD` 保留，feature flag 切换；任何试点失败可一键回旧 UI。
- 不迁移存档格式、不改网络协议、不改装备/任务数据结构；如必须改，单独评审并提供迁移/回滚。
- 每个试点交付：变更说明、截图 diff、JSON 审计、测试命令与结果、未验证项。

## 10. 阶段一出口条件

满足以下条件才进入阶段二/四：

1. 本文诊断被确认，尤其是“先结构后风格”的顺序。
2. 补证项（真实 4 人联机、手柄范围、暂停受伤、性能、加载异步性）有结论或明确接受为风险。
3. 试点范围锁定为：主菜单、联机大厅、战斗 HUD；背包/军械库仅打开关闭/焦点/样式，不扩展为完整重设计。
4. 建立回退标签与截图/JSON 基线；任何改动都能对比。
5. 不在证据不足时承诺“商业级完成”；所有未验证项在最终报告 E 中保留。
