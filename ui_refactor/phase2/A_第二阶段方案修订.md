# A · 第二阶段方案修订

> 工程基线：`c805ed5ff04ab56381cd36fe5b2e803164750cba`（`main`）  
> 依据：阶段一 A/B/C、README，以及当前 Godot 工程源码。  
> 性质：方案与接口设计，**本轮不改生产代码**。  
> 日期：2026-10-24。

## 0. 本轮决定

主菜单最终形态改为**叙事驱动的 CG 场景**，不再把现有低多边形 2D 夜景 + 信息面板当作最终主菜单。阶段一审计原则上保留，但工作拆成两条线：

- **工作线 A：游戏 UI 系统**——修信息架构、布局碰撞、对比度、焦点/输入、状态真实、组件复用；保留网络/战斗/存档/任务接口。
- **工作线 B：主菜单 CG 场景**——在 Blender 里做可建模、可编辑、可分层的观察室场景，输出无文字的纯净背景，再与 A 的安全区对接。

两条线不是“先做图，再摆 UI”，也不是“先改 UI，再找图”。它们通过 **D 文档的资产契约**并行推进，并以三个门禁对齐：

```text
B0 地点判定（B 文档）
   ↓
B1 白模 + 尺度 + 相机（Blender）
   ↓
A1 菜单线框 + 安全区（Godot 线框/截图）
   ↓
B2 最终构图锁定 → B3 资产 → B5 渲染
   ↓
B6 + D 集成（Godot 实机）
```

> 阶段一 C 曾写“不做全屏视频背景/角色特写之类需要新美术资产的方案”。那是一条**阶段一试点边界**，用于防止用装饰掩盖结构问题；现在用户明确新增“CG 主菜单”决定，该边界被本决定取代。但它的核心原则仍然有效：**CG 不能用来掩盖信息架构、布局和状态真实的问题**。

## 1. 体验模型

### 1.1 主菜单是什么

不是海报，也不是“游戏封面 + 一堆按钮”。它是：

> **部署前夜的一次静默观察**：玩家在安全区外侧的维护观察室里，看着基地与城市，决定何时出发。

因此：

- 背景负责“地点、时间、威胁、归处”；
- UI 负责“我是谁、去哪、怎么联机、现在什么状态”；
- 文字不进入 CG，避免本地化/分辨率/可访问性问题；
- 画面中央保留一个**不被常驻 UI 遮挡的叙事窗**；
- 菜单的“静”与战斗的“吵”形成对比，进入游戏时 CG 淡出。

### 1.2 信息优先级

| 优先级 | 信息 | 位置 | 现行问题 |
|---|---|---|---|
| 1 | 创建房间 / 加入房间 / 单人演练 | 左栏主行动区 | 与呼号、种子、IP、端口混在同一表单，首屏压力大 |
| 2 | 行动呼号、地图种子、主机地址、端口 | 部署终端（可展开） | 常驻占高，1280×720 下挤爆 |
| 3 | 当前状态（等待/连接/准备/错误） | 主行动区下方 | 文案与按钮状态偶有矛盾 |
| 4 | 行动简报（目标、规则、图例） | 右栏，可折叠/滚动 | 固定高度导致底部裁切 |
| 5 | 局外档案、军械库、退出 | 次级区/页脚 | 退出被内容流挤出 |
| 6 | 版本、引擎、网络模式 | 页脚 | 可以保留但降级 |

### 1.3 状态机与背景可见性

```text
BOOT
  └─ MENU（CG 背景 + 标题 + 主行动）
       ├─ DEPLOY_TERMINAL（联机设置弹层；CG 保留，加暗遮罩）
       ├─ LOBBY（CG 保留，右侧/中央显示队伍）
       ├─ ARMORY（CG 保留，强暗遮罩；或改为独立暗底）
       ├─ LOADING（CG 淡出/暗化；不确定进度）
       └─ PLAY（菜单隐藏；HUD 接管）
            ├─ PAUSE（场景保留，左侧信息列）
            ├─ OVERLAY（情报/背包/抽卡；场景保留或暗化）
            └─ RESULT（结算；返回大厅为唯一主操作）
```

规则：

- CG 背景只在 `MENU/LOBBY/ARMORY` 可见；进入 `LOADING` 后淡出，`PLAY` 中不渲染；
- 背景不接收输入、不参与焦点、不拦截鼠标；
- 弹层可以压暗背景，但不能把背景替换成另一张“海报”；
- 任何状态下，UI 都必须能独立回答“我在哪、我能做什么、为什么不能做”。

## 2. 工作线 A：游戏 UI 系统

### A0 · 基线与回归夹具（0）

**目标**：在改任何 UI 前，固定可比较的基线。

- 固定 commit、Godot 版本、分辨率矩阵；
- 复用阶段一 `ui_refactor/phase1/tools/ui_audit.gd` 的 49 次渲染夹具；
- 增加三个本轮必需的用例：
  1. 4 人队伍（模拟 4 条 roster 数据）；
  2. 菜单在 1280×720、1920×1080、1920×1200、2560×1080 下的完整首屏；
  3. 搬运核心 + 空仓 + 低血量三态叠加。
- 所有截图带分辨率、状态、构建号；没有截图的结论标 `UNVERIFIED`。

**验收**：基线截图可复现；后续每个 A 阶段都能与基线逐张对比。

### A1 · 菜单信息架构与 CG 安全区（P0）

**目标**：让主菜单在 1280×720 下不再溢出，并给 CG 留出真正的叙事窗。

**推荐方案 A（主方案）**：

- 左栏 0–36%：标题、副标题、**一个主按钮“部署”**、次级“联机设置”；
- “部署”打开部署终端（呼号/种子/主机/端口/创建/加入/单人），保留全部功能，但不再常驻；
- 右栏 76–100%：行动简报（目标、规则、图例），可折叠/滚动；
- 页脚 90–100%：局外档案、军械库、退出、版本；
- 中央 36–76% × 8–90%：HERO，不放常驻 UI；
- 弹层（部署终端/军械库/联机设置）可以临时覆盖 HERO，但关闭后必须恢复。

**保守方案 B（回退）**：

- 保留现有左栏表单常驻，但把右栏简报折叠，退出固定在页脚；
- 牺牲部分 HERO 宽度，保证功能可见性；
- 仅在方案 A 的 1280×720 线框无法容纳中文输入框时启用。

**硬指标**：

- 1280×720 下菜单内容最小高度 ≤ 720，无裁切、无滚动才能看到主行动；
- 4 条简报标题首屏可见，详情可滚动；
- 创建/加入/单人、呼号/种子/IP/端口、军械库、退出均可达；
- 不改变 `MainMenu` 对 `main.gd` 的信号名与参数。

**依赖**：D 文档的安全区契约；B1 白模的相机取景。

**验收**：线框截图 + 1280×720/1920×1080/1920×1200/2560×1080 四张实机截图；无重叠、无越界。

### A2 · 主题、焦点与输入（P0）

**目标**：把“补丁式硬编码”变成可复用系统，同时不破坏现有手感。

**主题**：

- 建立一个 `Theme` 资源（或等价缓存层），替代每次 `SystemFont.new()`；
- 颜色 token 沿用阶段一：`BG/PANEL/PANEL_SOFT/LINE/TEXT/MUTED/CYAN/AMBER/RED/GREEN/VIOLET/CORAL`；
- 字号层级收敛为 5 级（如 28/20/16/14/12），关键数值 ≥18，说明 ≥12；
- 按钮 `normal/hover/pressed/disabled/focus` 五态齐全；`focus` 不再是 `StyleBoxEmpty`；
- 面板圆角/边框/内边距统一；减少不透明面板数量。

**焦点**：

- 菜单打开时 `grab_focus()` 到主行动；
- 所有可点卡片（军械库、抽卡、背包装备）改为 `FOCUS_ALL`，有可见 focus 环；
- 弹层打开时做焦点陷阱，关闭时把焦点还给触发按钮；
- 鼠标悬停不抢焦点；键盘/手柄移动焦点时显示 focus 环。

**输入**：

- 新增 `InputMap` 动作，保留现有物理键作为默认绑定，避免改变老玩家手感；
- 手柄：左摇杆移动、右摇杆视角、扳机射击/瞄准、肩键切换、A 互动、B 返回、Start 暂停；
- UI：`ui_accept/ui_cancel/ui_focus_next/ui_focus_prev` 统一；
- 鼠标：菜单释放，游戏捕获；弹层打开释放，关闭后按状态恢复；单人暂停与联机暂停语义分开；
- 所有动作有 deadzone，不把“按住”误判为“点按”。

**非目标**：不在本阶段改武器手感、后坐力、移动速度；不引入新的战斗动作。

**验收**：键盘全流程；手柄全流程（需真实硬件，当前 `UNVERIFIED`）；焦点不丢失；关闭弹层后鼠标/焦点正确。

### A3 · 战斗 HUD 的布局与状态（P0/P1）

**布局**：

- 左上改为一个 `VBoxContainer`：队伍面板 → 任务面板，间距计算，不再固定 `y=190`；
- 队伍面板高度由内容决定：1 人紧凑，4 人完整；4 人时任务面板下移，但不重叠；
- 左下生命面板底部锚定，内容高度自适应，保证 `y + height ≤ 720 - 16`；
- 右下武器/弹药合并为一个“当前武器”块；备用武器降级；
- 下中交互提示单一来源；世界 `Label3D` 与 HUD 二选一；
- **删除底部常驻键位长条**；改为首次教学、按住帮助、暂停键位表；
- 右上小地图缩小，降低红框；击杀信息与地图的间距固定，不随内容跳。

**状态真实**：

| 状态 | 现在 | 应显示 |
|---|---|---|
| 搬运核心 | 弹药仍“就绪” | `搬运中 · 武器锁定`，弹药/武器禁用态 |
| 空仓 | 只换颜色 | `空仓 · R 换弹` + 颜色/图标双编码 |
| 换弹 | 只有文字 | 进度/剩余时间 + 不可射击 |
| 低血量 | 颜色 + 数字 | 数字、心电、暗角同层；不靠颜色 alone |
| 加载 | 假 64% | 不确定进度 + `正在生成街区 #seed` + 阶段文案；不可取消就不放取消 |
| 大厅 1/4 | “全员已准备”矛盾 | `等待队员加入 · 当前 1/4`；主按钮说明“可单人开始/等待队友” |
| 客户端准备 | 本地乐观翻转 | `准备中…` → 服务器广播后落定；失败可重试 |

**对比度/语义**：

- 底部 11px 提示在明亮地面 1.12:1：删除或改为高对比；
- 抽卡描述/琥珀卡 ≥4.5:1；
- 红色只用于危险/失败/低血量；小地图红框、`LIVE` 红点、`NIGHT 07` 改为中性/青色；
- 世界标签缩小、降透明度、拉远距离；只在准星附近出现；
- 命中标记/丧尸点不能只靠颜色，增加形状/描边。

**验收**：4 人时零重叠；1280×720 下生命面板不出底边；搬运/空仓/换弹三态截图；对比度实测 ≥4.5:1（关键文本）。

### A4 · 覆盖层、暂停与结算（P1）

- 统一 `OverlayShell`：遮罩强度、焦点陷阱、Esc/返回、打开释放鼠标、关闭恢复；
- 暂停：单人真暂停；联机服务器继续；暂停面板保留场景，显示“服务器仍在运行”、本地生命/倒地、队友状态；
- 军械库/背包：本阶段只做打开/关闭、焦点、禁用态、对比度，不扩展成新系统；
- 抽卡：3 张卡可聚焦，`focus/selected/disabled` 三态；描述压缩为标题→增益→一句说明→按键；
- 结算：`返回大厅` 为唯一主操作；统计与失败原因同层；去掉 600×380 卡片的大片空白；
- 所有覆盖层打开时，背景 CG 若可见则加暗遮罩，不替换。

**验收**：键盘/手柄可完成打开→操作→关闭；焦点回到触发点；暂停中受伤有可见反馈；结算不遮挡主操作。

### A5 · 状态适配层（P1，工程拆分）

阶段一 C 已给出目标分层。本轮不强制一次拆完，但要求：

- UI 不直接读网络/玩家内部状态；通过 `MenuState/HudState` 纯数据或现有 `set_*` facade；
- 列表型 UI（队伍、武器卡、抽卡、背包）由数据重建，尺寸由内容决定；
- 保留 `MainMenu` / `GameHUD` 的公开方法与信号；
- 新增视觉层可以内部替换，但不得让 `main.gd` 同时维护两套真相；
- 每个阶段可单独回退。

### A6 · 验证与验收（P0）

**必须做**：

- 49 次渲染夹具复跑（或等价矩阵），对比基线；
- 4 人队伍模拟：截图 + 面板矩形 JSON，零重叠；
- 菜单 4 分辨率：1280×720、1920×1080、1920×1200、2560×1080；
- 对比度计算：关键文本 ≥4.5:1，大字号 ≥3:1；
- 焦点路径：Tab/方向键/手柄，无死点、无丢失；
- 状态路径：1/4、2/4 未准备、4/4 全准备、客户端准备失败、断线、结算；
- 回退开关：关闭新 UI 后旧界面可用。

**当前无法做/待补证**：

- 真实手柄硬件测试；
- 4 人真实联机（需要 4 个客户端/网络环境）；
- 4K/超宽实机显示；
- macOS/Linux 字体回退；
- 真实玩家可用性测试。

以上在报告中必须标 `UNVERIFIED`，不能写成“已通过”。

## 4. 两条线的依赖与关键路径

```text
B0 ──→ B1 ──→ B2 ──→ B3 ──→ B5 ──→ B6
             ↑        ↑
A0 ──→ A1 ───┘        │
        │             │
        ├──→ A2 ──────┘（焦点/输入可并行）
        ├──→ A3（HUD 可并行）
        └──→ A4（覆盖层可并行）
D 契约在 A1/B1 后冻结，B2/B5 必须遵守
```

关键路径：**B0 → B1 → A1 → B2 → B3 → B5 → B6**。  
A2/A3/A4 可以在 A1 之后与 B1/B3 并行，但不能改变 D 契约里的安全区。

## 5. 保留契约与回退

### 5.1 不能改的接口

- `main.gd` 的 `@rpc` 名称/参数/权限；
- `_prepare_world()`、`_server_secure_core()`、`_handle_game_over()`、`_return_to_menu()` 的外部行为；
- `mission_site.gd` 的基地/B1/坡道/核心/出口坐标；
- `MetaProfile` 的存档结构、`WeaponCatalog` 的武器顺序/默认配装；
- `MainMenu` / `GameHUD` 对外信号与方法名。

### 5.2 可以内部替换的

- `MainMenu._build()` 的内部布局；
- `GameHUD` 的面板容器与样式；
- `MenuBackdrop` 的绘制（最终由 CG 背景替换，但保留为回退）；
- Theme 的生成方式（从每次新建改为缓存/资源）。

### 5.3 回退

- 每个阶段独立 commit；不混合“UI 结构 + CG + 网络”改动；
- 建议开关：
  - `ui_v2_menu_layout`（默认关，验收后开）；
  - `ui_v2_menu_background`（默认关；缺失自动回退 `MenuBackdrop`）；
  - `ui_v2_hud`（默认关）；
  - `ui_v2_input`（默认关；旧键位始终保留）。
- 回退验收：关闭开关后，旧菜单/旧 HUD/旧输入仍可完成创建、加入、单人、战斗、结算。

## 6. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| CG 资产延期 | 菜单无法定稿 | 先做 B1 白模；Godot 侧用占位图；`MenuBackdrop` 回退 |
| UI 安全区与 CG 构图打架 | 基地/标题互相压 | D 契约先冻结；A1 线框先于 B2 最终构图 |
| 风格不协调 | CG 像另一个游戏 | 1:1 尺度、同一色板、低多边形倒角、与游戏截图对比 |
| 文字被烘焙 | 本地化/分辨率灾难 | B 全流程禁止文字对象；验收用 OCR/人工双检 |
| 连续性穿帮 | 玩家在基地看到墙外没有观察室 | O3 只做菜单；若加进游戏另立变更；先做三角色视角对比 |
| 输入改动影响手感 | 老玩家不适 | 保留物理键；InputMap 只加不改；手柄可关 |
| 4 人/联机未测 | 上线才发现重叠/状态错 | A0 模拟数据 + 真实 4 客户端测试单列 |
| 性能/显存 | 菜单卡顿 | 静态图、压缩、2560 回退、异步加载 |
| 叙事未批准 | 设定返工 | B 文档只写“部署前夜”空镜；不命名角色/地名 |
