# C · CG 分件清单与制作方案

> 工程基线：`c805ed5ff04ab56381cd36fe5b2e803164750cba`  
> 依据：[B_首章场景定位论证.md](B_首章场景定位论证.md) 的 O3 方案；[A_第二阶段方案修订.md](A_第二阶段方案修订.md) 的工作线边界。  
> 性质：制作方案与分件清单，**本轮不启动 Blender、不产出模型/渲染**。  
> 日期：2026-10-24。

## 0. 交付物定义

最终交付不是“一张 AI 图”，也不是“游戏截图加滤镜”，而是：

1. 一个**可编辑的 Blender 工程**：建筑、道具、植被、环境、灯光、相机分集合；
2. 一套**分层渲染**的母版（EXR + sRGB PNG），可在不重做场景的情况下改雾、改光、改调色；
3. 一张**不含任何菜单文字/按钮/UI**的纯净背景；
4. 一份**安全区/裁切契约**（见 D），保证 16:9、16:10、21:9 下 UI 不压叙事主体；
5. 一个 Godot 可用的**静态背景 + 回退方案**；可选 6 秒循环，但不是首发必需。

**非目标：**

- 不做角色动画、不做剧情过场、不做配音；
- 不做可玩关卡、不改碰撞/任务/出生点；
- 不做写实照片级材质；目标是“低多边形电影感”，不是 3A 写实；
- 不把 UI 文字、标题、按钮、语言文案烘焙进任何层；
- 不照搬《最后生还者》的窗户、室内布置或具体构图。

## 1. 设计意图

### 1.1 一句话

> 一个贴着南墙外侧的维护观察室，窗内是人的痕迹，窗外是基地、城市和通往 B1 的黑暗轴线；没有人物出场，没有文字，威胁藏在雾和远处的熄灯街区里。

### 1.2 叙事三角

| 位置 | 画面角色 | 视觉语言 |
|---|---|---|
| 观察室（近景） | “看”的位置，人的痕迹 | 冷窗框、暖工作灯、旧桌面、无线电、无字地图 |
| 基地（中景） | “回”的位置，脆弱的安全 | 青色安全环、琥珀工作灯、圆形平台、箱子/弹药台 |
| 城市/公园/B1（远景） | “去”的位置，未知威胁 | 低多边形街区、雾、少量暖窗、公园暗口、B1 微弱青光 |

### 1.3 情绪曲线

- 静：没有战斗、没有丧尸直出、没有爆炸；
- 冷：月光、蓝灰雾、湿地面；
- 一点暖：基地灯、室内台灯、远处窗；
- 一点危险：红色警示灯、熄灭的街区、B1 的黑口；
- 结尾感：不是“结束”，是“还没出发”。

## 3. 相机与构图

### 3.1 相机参数（假设）

| 参数 | 值 |
|---|---|
| 相机 | `CAM_Menu_Master` |
| 传感器 | 36mm 宽；**sensor_fit = VERTICAL**，sensor_height = 20.25mm |
| 镜头 | 24mm |
| 16:9 裁切 FOV | 水平 73.7°，垂直 45.8° |
| 21:9 母版 FOV | 水平 90.0°，垂直 45.8° |
| 光圈 | f/8 |
| 对焦 | 18m（超焦距附近，前后都清晰） |
| 快门 | 静态，无运动模糊 |
| 相机位置 | `(12.0, 8.8, -109.5)` |
| 目标空物体 | `(-24.0, 0.8, -30.0)` |
| 俯仰 | 约 −5.3° |
| 构图 | 水平，无荷兰角 |

**为什么用 vertical sensor fit：** 如果使用 AUTO，21:9 母版的垂直 FOV 会被压到约 35°，基地会掉出画面；vertical fit 让 21:9 只增加左右翼，16:9 裁切保留同一垂直构图。这是母版/裁切契约的关键技术点。

### 3.2 构图分区

![安全区与画幅裁切](figures/fig04_safe_areas.svg)

在 1280×720 逻辑坐标下：

- **HERO**：x 36–76%，y 8–90%；放基地、城市轴线、公园/B1 微光、月亮；
- **UI-L**：0–36%；标题、主行动、部署终端；
- **UI-R**：76–100%；行动简报/状态；
- **UI-B**：90–100%；页脚/版本/退出；
- 标题安全区 5%，动作安全区 3%。

具体画面（假设）：

- 左下/中左：基地圆台的一部分，青色安全环被墙顶切掉一段；交付台/灯柱可见；
- 中央偏右：城市街区向远处收束，中央公园的暗口在远处；
- 右上：月亮与薄云；不要放在 UI-R 的正文后面；
- 窗框：左右/上下边缘可见，形成“观察”的框；不要做成《最后生还者》式的百叶窗/室内陈设复刻；
- 桌面：下缘一条暗色剪影，放无线电/杯子/无字地图；不抢 HERO。

### 3.3 视线复核

- 相机到基地中心：墙顶净空约 **0.445m**（B 文档计算）；
- 基地南缘被墙顶遮挡，形成前景遮挡；这是可接受的；
- 基地中心/交付台可见；如果 blockout 发现交付台被挡，优先把相机抬高 0.2–0.4m，而不是移动基地；
- 远处公园/B1 口在 100m+，只作为“暗口 + 微光”，不要求看清细节；
- 画面中不得出现第二条坡道/传送门/高架。

## 4. 近景、中景、远景

### 4.1 近景 0–3m：观察室

- 窗框、窗台、桌面边缘、无线电、杯子、无字地图、线缆、工作灯；
- 材质以暗金属/旧木/织物为主，粗糙度高；
- 细节只做剪影级，不做可读文字/品牌/数字；
- 这一层负责“人刚刚离开”的叙事，不负责信息。

### 4.2 中景 3–60m：墙、基地、街区边缘

- 墙顶/红色条带、基地圆台、安全环、交付台、弹药台、箱子、灯柱；
- 街区低层建筑、路灯、车辆、围挡、树；
- 这一层是“安全 vs 城市”的对比，必须有明确的青色/琥珀/冷蓝关系；
- 不要在中景放高对比白色物体，避免抢 UI。

### 4.3 远景 60–212m：城市、公园、B1、天际线

- 中央公园的暗口、B1 入口的微弱青光/琥珀光；
- 程序化街区的体块、少量暖窗、屋顶水箱/天线；
- 边界墙的远处延伸、雾、烟柱、月亮；
- 这一层可以简化，但不能出现与游戏矛盾的高架/桥/塔。

### 4.4 空气与尺度

- 雾密度低，近清远浊；用 Mist/Volume 分层控制；
- 月亮高度低，天空占画面上方约 1/4；
- 城市尺度 1:1：街区 28m、道路 12m、建筑 2–6 层（6.4–20m）、墙 5.2m；
- 不把建筑做成电影里常见的 40–60m 高楼，否则与游戏尺度冲突。

### 6.2 材质规则

- 全部 Principled BSDF；粗糙度范围：
  - 混凝土 0.75–0.9；
  - 湿沥青 0.2–0.35（低粗糙度 + 轻微法线）；
  - 旧金属 0.35–0.6，带锈/划痕；
  - 玻璃 0.05–0.15 粗糙度，薄透明；不做强焦散；
  - 织物 0.85–0.95；
  - 木头 0.6–0.8。
- 纹理以程序化噪声/渐变为主，避免照片贴图；如用外部贴图，必须 CC0/自有，记录来源与许可证。
- 不做可读文字/数字/Logo；地图只做等高线/色块；仪表只做刻度线，不做数字。
- 湿润只做“局部反光”，不做全屏镜面；避免抢 UI。
- 所有材质进入 `MAT_Library`，参数化湿度和脏污，便于统一调整。

### 6.3 低多边形语言

- 大面、硬边、2–4cm 倒角；不要 microdetail；
- 建筑窗户用发光面片，不做窗框细分；
- 树用 2 层锥体 + 树干；车用 3–4 个盒子 + 轮子；
- 栏杆/线缆在 1280×720 下至少 2px，否则删除；
- 远景只做体块/轮廓，不做窗格；让雾和光完成细节。

## 7. 灯光、天气、时间、色彩管理

### 7.1 时间与天气

- **主方案**：深夜/蓝调时刻，月亮低垂，薄雾，轻落灰，地面微湿；
- 不选暴雨：雨丝会遮挡 UI/降低可读性；如要做，只作为远景，不落在窗面上；
- 不选正午/黄昏：与游戏的夜战气质冲突；
- 可选变体 B：更浓的雾/更高的月亮，作为后续季节性版本；首发只做一张。

### 7.2 灯光结构

| 层 | 光 | 作用 |
|---|---|---|
| 主 | 冷月光（低角度、略侧逆） | 城市轮廓、墙顶、窗框 |
| 辅 | 天空渐变/环境光 | 暗部不死黑 |
| 点 | 基地暖灯、安全环青光、红色警示 | 视觉锚点 |
| 近 | 室内工作灯（暖、低） | 人的痕迹 |
| 轮廓 | 窗框冷边光 | 分离前景与城市 |
| 远 | B1 微弱青光、少量窗光 | 目的地/尺度 |

### 7.3 色彩管理

- Blender：Scene Linear → AgX（或 Filmic，二选一，不要混）→ sRGB；
- 曝光 0，Look 用 Medium High Contrast 起步；最终以与游戏截图对比为准；
- 渲染 16-bit EXR 母版；合成后输出 8-bit sRGB PNG（Godot 用）；
- 不在 Godot 里再叠加一次 gamma；导入设置为 sRGB；
- 输出前做一张色卡/灰阶测试，确认天空没有条带、暗部没有死黑、青色没有偏色；
- UI 颜色由 Theme 管理，CG 不承担语义色；红色只用于危险点，面积要小。

### 7.4 与游戏环境的一致性

游戏环境：天空顶 `#070d18`、地平线 `#27313c`、雾 `#1b2833`、密度 0.006、Filmic、曝光 1.05、glow 0.45、月光 `#b9cfe8`。证据：`scripts/main.gd:661-686`。

CG 不要求逐像素一致，但要保持：

- 同一冷暖关系（冷城市 + 暖基地 + 青安全）；
- 同一雾的密度感（远景灰蓝，不泛白）；
- 同一月光方向（低角度、侧逆）；
- 同一低多边形尺度（墙 5.2m、街区 28m、建筑 2–6 层）。

## 9. 分层渲染、合成、输出

### 9.1 View Layers

| View Layer | 内容 | 用途 |
|---|---|---|
| `VL_Foreground` | 观察室、窗框、桌面、室内灯 | 前景控制 |
| `VL_Base` | 基地平台、交付台、灯柱、箱子 | 中景锚点 |
| `VL_City_Mid` | 近中街区、路灯、车、树 | 中景 |
| `VL_City_Far` | 远景楼、公园、B1 入口、墙延伸 | 远景 |
| `VL_Atmos` | 雾、体积、烟、落灰 | 空气 |
| `VL_Practicals` | 自发光/实用灯（可用 Emission pass） | 辉光 |
| `VL_Depth` | Depth/Mist | 合成/景深 |

### 9.2 Passes

- Combined（Beauty）
- Depth
- Mist
- Emission
- AO
- Cryptomatte（Object/Material）
- Normal（可选，后期微调）

### 9.3 合成顺序

```text
Sky/Far
  → City_Far
  → Atmos (fog/volume)
  → City_Mid
  → Base
  → Foreground
  → Practicals glow
  → Grade (AgX/Filmic → sRGB)
  → Vignette (很轻)
  → Grain/Dither (防条带)
```

规则：

- 辉光只加在实用光源/安全环/窗光，不整体泛光；避免 UI 对比度下降；
- 雾用 Mist/Volume 分层，不在合成里用一张大渐变糊死；
- 暗角很轻（≤8%），不要压住 HERO；
- 颗粒 1–3%，用于天空防条带，不要做成“胶片噪点”；
- 局部调色用 Cryptomatte 选基地/窗框，不整体偏色。

### 9.4 输出

| 文件 | 尺寸 | 色彩 | 用途 |
|---|---|---|---|
| `menu_bg_master_21x9_v001.exr` | 5120×2160 | Linear/AgX | 母版/后续调色 |
| `menu_bg_master_21x9_v001.png` | 5120×2160 | sRGB | 21:9 |
| `menu_bg_16x9_v001.png` | 3840×2160 | sRGB | 16:9 主交付 |
| `menu_bg_16x10_v001.png` | 3456×2160 | sRGB | 16:10 可选 |
| `menu_bg_contract_v001.json` | — | — | 安全区/版本/哈希 |

- 采样：Cycles 256–512 + OIDN；静帧无需运动模糊；
- 渲染时间：4K 单帧在中端 GPU 上约 20–60 分钟（估算，需实测）；不承诺具体机器；
- 输出前检查：无文字、无 UI、无可见接缝、天空无条带、暗部有细节、青色不偏紫。

## 10. Godot 集成

### 10.1 节点

```text
MainMenu (Control)
├─ MenuBackground (TextureRect)
│  ├─ expand_mode = EXPAND_IGNORE_SIZE
│  ├─ stretch_mode = STRETCH_KEEP_ASPECT_COVERED
│  ├─ mouse_filter = MOUSE_FILTER_IGNORE
│  └─ anchors = full rect
├─ Scrim (ColorRect/TextureRect)
├─ MenuContent (Control)
└─ Overlays (Control)
```

### 10.2 导入

- 纹理导入：sRGB、mipmaps on、filter linear、repeat off；
- 4K 可先用 VRAM 压缩（BC7/ASTC）或 2560×1080 回退；具体压缩质量需实测；
- 预加载/异步：菜单是首屏，建议 `ResourceLoader.load_threaded_request` + 占位/淡入；如果加载失败，回退 `MenuBackdrop`；
- 背景不参与 `_process`，不每帧重绘；现有 `MenuBackdrop` 的每帧 `queue_redraw()` 在隐藏时应停止（阶段一 PERF 项）；
- 背景 `z_index` 低于 UI；`show_behind_parent` 不需要，按子节点顺序即可；
- 不把背景放进 `SubViewport`，避免额外渲染成本。

### 10.3 内存估算

| 尺寸 | RGBA8 | RGB8 | BC7 近似 |
|---|---:|---:|---:|
| 5120×2160 | 44.2MB | 33.2MB | 11.1MB |
| 3840×2160 | 33.2MB | 24.9MB | 8.3MB |
| 2560×1080 | 11.1MB | 8.3MB | 2.8MB |

（未计 mipmap；mipmap 约 +33%。数字为估算，需在目标机实测。）

### 10.4 显示策略

- `MENU/LOBBY`：显示 CG；`ARMORY`：加暗遮罩；`LOADING`：淡出；`PLAY`：隐藏；
- 背景不拦截鼠标/焦点；
- 可选的落灰/轻微呼吸用引擎侧 2D 粒子，放在背景之上、UI 之下；提供“减少动态”开关；
- 不做默认视频循环：静态图 + 轻动效更省、更稳、更易本地化；如要做 6 秒循环，另立交付（1920×1080 WebM，无缝，无文字）。

## 11. 与现有低多边形风格的协调

| 维度 | 游戏 | CG | 规则 |
|---|---|---|---|
| 尺度 | 街区 28m、墙 5.2m、建筑 2–6 层 | 1:1 | 不改尺度 |
| 形体 | 盒子/圆柱/锥体，硬边 | 同 | 只加 2–4cm 倒角 |
| 色彩 | 深青绿 + 琥珀 + 危险红 | 同 | 不引入新语义色 |
| 光照 | Filmic、glow 0.45、雾 0.006 | 近似 | 对比截图校准 |
| 细节 | 低模、窗面片、无内饰 | 稍多但不写实 | 不做照片纹理/微细节 |
| 相机 | 78° 第一人称 | 24mm 电影感 | 菜单可以更窄，但不能变成别的游戏 |
| 天空 | 程序化夜空 | 同色系 | 月亮/星/雾一致 |

**风格测试**：B1 白模先出 1280×720 平色渲染，与阶段一 `mission_base_1280x720.png`、`combat_1280x720.png` 并排；如果第一眼像“另一个游戏”，先改尺度和色板，不要加细节。

**禁止的“电影感”捷径**：

- 不要用照片贴图/扫描资产把低模盖成写实；
- 不要加镜头光晕/色差/景深糊成“3A 预告片”；
- 不要用 TLOU 的窗户/室内布置/人物构图；
- 不要为了气氛把画面压到全黑，UI 文字会读不清。

## 12. 制作流程、工时与可行性

### 12.1 流程

1. **B0 地点评审**：确认 O3 菜单专用、不改任务；确认“桥下/高架”不作为正史。
2. **B1 白模**：用盒子/圆柱搭墙、基地、观察室、城市体块；1:1；相机 24mm；出 1280×720 平色图；复核基地/窗框/远景。
3. **B2 构图锁定**：与 A1 菜单线框叠加；确认 HERO/UI 安全区；锁定相机、窗宽、目标点；出 16:9/21:9 两张线框图。
4. **B3 资产**：按分件表做建筑套件、道具、植被；每个模块单独 `.blend`；用 collection instance 组装；控制面数。
5. **B4 灯光/材质**：先材质球/色板，再布光；与游戏截图对比；做雾/落灰/湿地面；锁定色彩管理。
6. **B5 渲染/合成**：View Layers + passes；合成；输出 EXR/PNG；做 16:9/16:10/21:9 裁切检查；OCR/人工双检无文字。
7. **B6 集成**：Godot `TextureRect` + 回退；4 分辨率实机；显存/加载测试；与 UI 叠加对比；冻结版本。

### 12.2 工时估算

| 阶段 | 估算（1 人） | 说明 |
|---|---:|---|
| B0 | 0.5–1 天 | 评审为主 |
| B1 | 1–2 天 | 白模/尺度/相机 |
| B2 | 0.5–1 天 | 构图/安全区 |
| B3 | 3–5 天 | 资产套件 |
| B4 | 2–3 天 | 灯光/材质/雾 |
| B5 | 1–2 天 + 渲染 | 合成/输出 |
| B6 | 0.5–1 天 | 集成/回退 |
| 合计 | **8–15 人日** | 不含评审/返工；估算，不是承诺 |

### 12.3 硬件/软件

- Blender 4.x + Cycles；GPU 8GB+ VRAM、32GB RAM 起步；4K 渲染建议 12GB+；
- 不需要角色/布料/流体模拟；落灰用几何节点/粒子，雾用体积；
- 不需要外部付费资产；如用 CC0 贴图，记录来源/许可证；
- 不需要 Houdini/Nuke；Blender Compositor 足够；如团队有 DaVinci，可选。

### 12.4 可行性判断

**可建模**：全部由盒子/圆柱/锥体/面片构成，无雕刻、无角色绑定、无复杂模拟。  
**可编辑**：建筑/道具/植被/环境/灯光/相机分集合；资产库 link；参数化材质。  
**可制作**：一人 8–15 人日可出首版；主要风险是资产套件膨胀和构图返工，不是技术不可行。  
**可回退**：Godot 侧始终保留 `MenuBackdrop`；CG 缺失不影响游戏运行。
