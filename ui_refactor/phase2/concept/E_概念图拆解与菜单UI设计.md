## 0. 一句话回答

如果我拿到这样一张概念图，我不会先照着它做界面，更不会把它当背景直接塞进游戏。我会按这个顺序处理：**登记来源与用途 → 拆成 CG 层 / UI 层 / 字体层 → 和实际工程对账 → 判定“可保留 / 必须修改 / 禁止照搬” → 先用可交互原型验证布局与状态 → 再让 CG 工作线按“无文字、21:9 母版、明确安全区”去制作 → 最后在 Godot 里合成与验收。**

这张图能提供的是**氛围与明暗关系的参考**；它不能提供的是工程事实、可运行场景、无文字背景或验收证据。

## 1. 这张图是什么，不是什么

| 它是 | 它不是 |
|---|---|
| 一张 16:9 的合成概念稿，带标题、菜单、页脚等烘焙文字 | 可运行的 3D 场景，或可编辑的 Blender 工程 |
| 氛围、明暗分区、信息密度的参考 | 工程事实：图中 E-07、高架、列车在现工程中均检索不到 |
| UI 布局与选择态的讨论起点 | 最终背景资产：文字必须由 UI 层渲染，不能烘焙 |
| 对“左暗右亮、窗作视觉框”的一次具体化 | 可直接照搬的构图：窗型、室内布置与 TLOU 过近 |

> 来源判断：从视觉特征看，它更像 AI 合成/概念稿，而不是实际渲染。无论来源如何，在本项目里它只能作为**参考**，不能作为“场景已完成”的证据。

## 2. 先对账，再设计

### 2.1 与工程事实对账

| 概念图中的元素 | 现工程状态 | 判定 |
|---|---|---|
| “E-07 高架维护观察室” | 全工程检索不到 `E-07`；无章节/地点编号系统 | `NOT FOUND`，不能写成既定正史 |
| 高架轨道、混凝土高架、列车 | 无桥、无高架、无轨道、无列车；`CityLayout`/`CityBuilder` 不生成 | `NOT FOUND`，采用即新增设定 |
| “旧维护观察室”室内 | 无可进入的二层室内；可进入建筑是单房间壳 | `NOT FOUND`，只能做菜单专用布景 |
| 南墙内侧基地 | 中心 `(0,0.16,-98)`、半径 7m 的开放圆形平台 | `STATIC_VERIFIED` |
| 公园坡道 → B1 | 坡道 `z=12.6 → -8.2`，B1 `y=-14`，唯一出口是同一坡道 | `STATIC_VERIFIED` |
| 章节/剧情系统 | 无章节系统；只有 `MetaProfile.history` | `NOT FOUND`；“首章”只能指当前首次部署循环 |

结论：**这张图把此前被否定的“高架二层”以菜单专用设定的形式又带回来了。** 它可以存在，但必须满足三个条件：

1. 明确是**菜单专用、不可进入、与第一章任务无关**的叙事布景；
2. 由叙事/关卡签字，不能写成玩家可到达的地点，不能改任务常量、出生点、碰撞；
3. 如果叙事不批准，就退回 O3（南墙外侧观察室）或 O5（现有南墙/基地轴线），不采用图中的高架与列车。

### 2.2 与 UI 状态对账

| 概念图呈现 | 需要补上的真实状态 |
|---|---|
| “继续行动”始终可点 | 无存档时必须禁用，并说明“暂无可用存档”；有存档时显示最近进度摘要 |
| “联机作战”始终可点 | 离线/未登录/无网络时要有明确状态，不能假装可进入 |
| 6 个菜单项一列排开 | 联机大厅、军械库、设置是独立覆盖层/场景，不应挤在根菜单 |
| 选择态是琥珀色 + 白字 | 还需要形状线索（括号、箭头、缩进）与可见焦点；不能只靠颜色 |
| 页脚地点固定 | 地点名是叙事设定；未批准前必须标注“待确认”，不能当既定事实 |
| 16:9 一张图 | 需要 21:9 母版、16:9/16:10 中央裁切；文字不能随背景拉伸 |

### 2.3 与参考边界对账

图中“大工业窗 + 藤蔓 + 前景桌面 + 电台/杯子 + 地图 + 金色逆光”的组合，与《最后生还者》系列的菜单气质非常接近。任务书明确禁止照搬其窗户、室内布置或具体构图。因此：

- **保留的是方法**：左暗右亮、窗作为视觉框、低信息密度、暖色选择标记；
- **不保留的是具体造型**：大扇多格窗、藤蔓帘、桌面物件组合、正面对称机位、金色逆光都要重做；
- **重做方向**：换窗型（横向窄窗/破损百叶/高侧窗）、换房间功能（交通维护值班室：配电柜、线路图、反光背心、工具箱，而不是杯子+电台的“生活感”组合）、换机位（偏轴、低机位、局部遮挡）、换色温（冷暮色+钠灯，或阴天+局部暖光），让画面服务于本作，而不是像另一款游戏的延续。

## 3. 拆解：可保留 / 必须修改 / 禁止照搬

| 类别 | 条目 | 处理 |
|---|---|---|
| 可保留 | 左侧暗部承载文字、右侧亮部承载视觉焦点 | 保留为构图原则 |
| 可保留 | 窗/门洞作为“看向城市”的视觉框 | 保留原则，窗型必须重做 |
| 可保留 | 标题与菜单左对齐、单列、低密度 | 保留；这正好解决阶段一的菜单高度溢出与信息拥挤 |
| 可保留 | 琥珀色细括号 + 白字 + 副标题的选择态 | 保留，并加箭头/缩进，避免只靠颜色 |
| 可保留 | 页脚一行地点/版本信息 | 保留结构；地点名待叙事确认 |
| 必须修改 | 所有烘焙文字（标题、菜单、副标题、页脚） | 全部移除；文字只由 UI 层渲染 |
| 必须修改 | 副标题约 4.2:1、页脚约 1.4:1 的对比 | 正文与页脚信息目标 ≥4.5:1；大字号 ≥3:1 |
| 必须修改 | “继续行动”无存档仍可点 | 按 `MetaProfile` 真实状态启用/禁用 |
| 必须修改 | 选择态只有颜色变化 | 加括号、箭头、缩进；键盘/手柄焦点可见 |
| 必须修改 | 16:9 单画幅 | 21:9 母版 + 16:9/16:10 裁切；左右翼区补内容，不拉伸 |
| 禁止照搬 | TLOU 的窗型、室内布置、具体构图 | 重做窗、房间功能、机位与道具组合 |
| 禁止照搬 | 把 AI 概念图当场景完成证据或直接做背景 | 只做参考；背景必须来自可编辑 CG 工程 |
| 禁止照搬 | 为菜单视觉改写第一章任务逻辑 | 菜单专用布景与任务空间解耦 |

> 对比值为对概念图像素的估计（副标题 4.21:1、页脚 1.39:1、普通菜单 5.07:1、选中 17.65:1、标题 13.98:1），不是最终验收值。最终必须在实际渲染、实际字体、实际遮罩上复测。

## 4. 菜单信息架构

### 4.1 根菜单只保留六项

```
死城突围
在崩塌的世界，寻找回家的路

[继续行动]        从上次离开的地方继续        ›
 单人行动
 联机作战
 ─────────
 角色整备
 设置
 退出

| E-07 高架轨道 · 旧维护观察室（待确认）      UI 原型 · 非最终
```

- **取消**现有主菜单右侧的常驻信息面板；联机大厅、军械库、设置、情报都改为独立覆盖层/场景。
- 根菜单只承担“进入哪条路径”，不承载房间列表、装备详情、任务简报。这样从结构上消除阶段一的最小高度 741 > 720、四名玩家名单 243 > 164 等溢出。
- “继续行动”是唯一带副标题的项；其余项保持单行，降低视觉噪声。

### 4.2 状态矩阵

| 状态 | 继续行动 | 单人行动 | 联机作战 | 角色整备 | 设置 | 退出 |
|---|---|---|---|---|---|---|
| 无存档 | 禁用 + “暂无可用存档” | 可用 | 可用 | 可用 | 可用 | 可用 |
| 有存档 | 可用 + 最近进度摘要 | 可用 | 可用 | 可用 | 可用 | 可用 |
| 离线 | 按存档 | 可用 | 禁用/提示“需要网络” | 可用 | 可用 | 可用 |
| 主机 | 按存档 | 可用 | 可用（创建/加入） | 可用 | 可用 | 可用 |
| 客户端 | 按存档 | 可用 | 可用（加入） | 可用 | 可用 | 可用 |
| 游戏中 | 不显示根菜单 | — | — | — | — | — |

规则：

- 初始焦点落在**第一个可用项**；无存档时不得停在禁用项上。
- 上下键循环；到达两端时回绕；禁用项跳过。
- `Enter/Space` 确认；`Esc` 返回上一层；在根菜单按 `Esc` 不退出游戏，只提示。
- 鼠标悬停只改变高亮，不抢键盘焦点；点击后才进入该项。
- 退出必须二次确认；联机中退出要说明会断开房间。
- 不显示假进度、假人数、假延迟；所有状态来自真实适配器。

### 4.3 覆盖层关系

```
MenuRoot
├── 继续行动 → 读取存档 → 部署
├── 单人行动 → 部署确认（难度/装备摘要）
├── 联机作战 → 大厅覆盖层（创建/加入/准备）
├── 角色整备 → 军械库覆盖层
├── 设置 → 设置覆盖层（显示/音频/控制/无障碍）
└── 退出 → 二次确认
```

覆盖层统一使用 `OverlayShell`：遮罩、焦点陷阱、`Esc` 关闭、打开时暂停背景输入、关闭后焦点回到来源按钮。阶段一审计中的覆盖层焦点与状态问题在这里一并解决。

## 5. 视觉系统

### 5.1 字号（1280×720 逻辑）

| 层级 | 字号 | 字重 | 用途 |
|---|---:|---|---|
| 标题 | 64 | 900 | “死城突围” |
| 副标题/标语 | 11 | 400，字距 0.34em | 一句气质文案 |
| 主行动 | 25 | 500 | 继续行动 |
| 普通项 | 21 | 500 | 单人/联机 |
| 次项 | 18 | 400 | 整备/设置/退出 |
| 说明 | 11 | 400 | 主行动副标题 |
| 页脚 | 10 | 400，字距 0.13em | 地点/版本 |

标题字体当前用系统宋体/思源宋体重字重替代；商业发布前必须换成**有授权**的中文展示字体，并单独做字形测试。不要用 AI 生成的标题字当最终 logo。

### 5.2 颜色与对比

| Token | 值 | 用途 | 在近黑底上的对比（原型） |
|---|---|---|---|
| `ink` | `#f3ede3` | 标题 | 约 17.5:1 |
| `ink-2` | `#d9d0c2` | 菜单默认 | 13.28:1 |
| `muted` | `#b6aa99` | 副标题/页脚 | 8.88:1 |
| `muted-2` | `#968b7d` | 次要说明/禁用 | 6.07:1 |
| `amber` | `#e6a75e` | 选择标记/箭头 | 9.71:1 |
| 选中白 | `#ffffff` | 选中项 | 20.28:1 |
| 背景 | `#050607` | 左侧遮罩底 | — |

- 原型左侧是 99% 不透明的遮罩，因此上述对比很高；**最终 CG 的左区亮度必须单独复测**，不能把原型数值当成 CG 的保证。
- 页脚是信息，不是装饰；目标 ≥4.5:1，不用概念图里接近 1.4:1 的暗金。
- 选中态不只靠颜色：细括号 + 箭头 + 文字变白 + 5px 缩进，四种线索叠加。

### 5.3 间距与锚点

| 元素 | 1280×720 逻辑 | 说明 |
|---|---|---|
| 左列 left | 5.2% ≈ 66px | 在 5% 标题安全线内 |
| 左列 top | 12.4% ≈ 89px | 标题顶部 |
| 左列宽 | 34%，max 440px | 不进入 HERO |
| 菜单起点 | 约 y=290 | 标题下方留 90px |
| 页脚 bottom | 6.2% ≈ 45px | 在 90–100% UI-B 内 |
| 右下提示 | bottom 5.4% | 不挡页脚 |

21:9 时左列不随宽度等比放大，只保留左侧锚点；多出来的宽度全部给 CG 翼区。16:10 时上下多出的高度由背景 cover 裁切，UI 仍按百分比锚定。

### 5.4 安全区

沿用 D 契约：

| 区域 | 1280×720 | 规则 |
|---|---|---|
| UI-L | 0–36%（0–461px） | 标题、主行动、菜单；常驻文字只在这里 |
| UI-R | 76–100%（973–1280px） | 可放状态/简报；本方案根菜单留空 |
| UI-B | 90–100%（648–720px） | 页脚、版本、退出提示 |
| HERO | 36–76% × 8–90% | 基地/城市/窗/月亮；不得被常驻 UI 遮挡 |
| Title safe | 5% | 标题与菜单的硬边界 |
| Action safe | 3% | 所有可交互元素 |

注意：概念图是 16:9；如果直接做 21:9 母版，左右各需新增约 320px 的翼区，不能拉伸。16:10 取中央 3456/5120；16:9 取中央 3840/5120。

### 5.5 动效

- 选择：120–180ms 的括号淡入、文字 5px 位移、箭头淡入；不做整行横移。
- 覆盖层：180–220ms 淡入 + 8px 上移；关闭反向。
- 背景：默认静态；可选 6 秒极慢呼吸/尘埃循环。`prefers-reduced-motion` 或游戏内“减少动态”开启时全部关闭。
- 不做镜头漂移、不做景深呼吸、不做高频粒子；这些会干扰阅读，也会增加晕动风险。

### 6.4 原型里哪些是模拟的

- 继续/单人/联机/整备/设置/退出：只弹提示，没有真实场景切换。
- 无存档：由 `N` 键模拟，没有读 `MetaProfile`。
- 联机人数/延迟/准备状态：未实现。
- 背景：概念图或 CSS 占位，不是 CG。
- 手柄：未接入；只用键盘/鼠标验证。
- 回退：占位背景是视觉占位，不是运行时缺图回退逻辑。

## 7. Godot 落地映射

### 7.1 节点树（建议）

```
MenuRoot (Control, full rect)
├── Backdrop (TextureRect)            # 最终 CG；expand=IGNORE_SIZE, stretch=KEEP_ASPECT_COVERED
├── ScrimLeft (TextureRect)           # GradientTexture2D 横向多段；不烘焙进 CG
├── ScrimBottom (TextureRect)         # 纵向渐变
├── Vignette (TextureRect/ColorRect)  # 可选
├── SafeArea (Control, anchors)
│   └── MenuColumn (VBoxContainer)
│       ├── Lockup (VBoxContainer)
│       │   ├── Title (Label)
│       │   └── Tagline (Label)
│       ├── MenuList (VBoxContainer)
│       │   ├── ContinueButton (MenuButton)
│       │   ├── SoloButton (MenuButton)
│       │   ├── CoopButton (MenuButton)
│       │   ├── Rule (ColorRect)
│       │   ├── LoadoutButton (MenuButton)
│       │   ├── SettingsButton (MenuButton)
│       │   └── QuitButton (MenuButton)
│       └── Footer (HBoxContainer)
├── Hint (Label)
├── Toast (PanelContainer + Label)
├── OverlayHost (Control)             # 大厅/军械库/设置/退出确认
└── DebugGuides (Control, hidden)     # 仅开发构建
```

`MenuButton` 是自定义场景/脚本，不是每个按钮单独写样式：

```
MenuButton (Button, focus_mode=FOCUS_ALL)
├── SelectionMark (Control, custom _draw 或 NinePatchRect)
├── LabelColumn (VBoxContainer)
│   ├── NameRow (HBoxContainer)
│   │   ├── Name (Label)
│   │   └── Chevron (Label/TextureRect)
│   └── Sub (Label, optional)
```

### 7.2 Theme

- 在 `ui_theme.gd` 里增加菜单 token：`MENU_INK`、`MENU_MUTED`、`MENU_AMBER`、`MENU_SCRIM`、`MENU_RULE`；字号、字距、行高统一。
- `Button` 的 normal/hover/pressed/disabled/focus 全部由 Theme 提供；`focus` 不再是 `StyleBoxEmpty`（阶段一 UX 问题）。
- 选中态由 `MenuButton` 自己根据 `has_focus()` 绘制括号/箭头，或用 `StyleBoxFlat` 的左边框 + 一个 `Chevron` 子节点；不要在每个按钮里复制 163 个 `add_theme_*` 覆盖。
- 禁用态用 Theme 的 disabled 颜色，而不是运行时把整个节点 `modulate.a` 调到 0.38（后者会让文字对比不可控）。

### 7.3 InputMap

当前 `project.godot` 没有 `[input]` 段，也没有手柄映射。需要新增（本轮不执行）：

| Action | 键盘 | 手柄 |
|---|---|---|
| `menu_up` | `Up` / `W` | D-pad Up / 左摇杆 Up |
| `menu_down` | `Down` / `S` | D-pad Down / 左摇杆 Down |
| `menu_accept` | `Enter` / `Space` | A / Cross |
| `menu_back` | `Esc` | B / Circle |
| `menu_toggle_guides` | `F1`（仅开发） | — |

实现要点：

- `_unhandled_input` 不再直接读物理键；统一走 InputMap。
- 每个 `MenuButton` 设置 `focus_neighbor_top/bottom` 形成环；禁用项从环里移除或跳过。
- 打开菜单时 `grab_focus()` 到第一个可用项；关闭覆盖层后焦点回到来源按钮。
- 鼠标 `mouse_entered` 只做高亮，不在悬停时抢焦点；点击后再 `grab_focus()`。
- 手柄断开/重连时重新计算可用焦点，避免焦点停在不可见项。

### 7.4 状态适配

建议新增一个只读适配器（不改现有存档/网络接口）：

```gdscript
class_name MenuState
extends RefCounted

var has_save: bool = false
var save_summary: String = ""
var network_mode: String = "offline" # offline / host / client
var can_coop: bool = false
var coop_note: String = ""
```

- `has_save` / `save_summary` 从 `MetaProfile` 读取；没有就禁用“继续行动”。
- `network_mode` 从现有网络层读取；不新增 RPC，不改 `main.gd` 的权威逻辑。
- 所有 UI 只消费 `MenuState`，不在按钮回调里临时判断文件是否存在。
- 联机大厅仍沿用现有 `update_lobby` / ready / start 逻辑；只换表现层，不改协议。

### 7.5 背景集成

- `TextureRect`：`expand_mode = TextureRect.EXPAND_IGNORE_SIZE`，`stretch_mode = TextureRect.STRETCH_KEEP_ASPECT_COVERED`，`mouse_filter = IGNORE`。
- 异步加载：`ResourceLoader.load_threaded_request()` + 每帧 `load_threaded_get_status()`；加载完成前显示现有 `MenuBackdrop` 程序化夜景，避免黑屏。
- 缺图/加载失败：回退到 `MenuBackdrop`，并记录一次 warning；不能显示空白或错误贴图。
- 显存：一张 5120×2160 RGBA PNG 解压后约 42MB（未压缩估算），实际取决于导入压缩；1080p 可另做 2560×1080 衍生图。**未实测**，不要写进验收为“已通过”。
- 色彩：Blender 线性 → AgX/Filmic → sRGB PNG → Godot sRGB；不要在 Godot 再套一次 gamma。
- 静态背景不需要 mipmap；但缩小显示时建议开启 mipmap 或提供对应分辨率衍生图，避免摩尔纹。**待实机验证**。

### 7.6 迁移顺序

1. 先做 `MenuButton` + Theme token + InputMap（A2），不动业务逻辑。
2. 用现有 `MenuBackdrop` 替换根菜单布局，验证 1280×720、16:10、21:9 与手柄焦点（A1/A2）。
3. 接入 `MenuState`，验证无存档/有存档/离线/联机状态（A5）。
4. CG 到位后只替换 `Backdrop.texture`，保留 `ScrimLeft` 与回退；不改菜单结构（B5/B6）。
5. 最后做覆盖层统一（A4）与验收（A6）。

## 8. CG 工作线需要交付什么（给 B 的接口）

1. **无文字**：标题、菜单、副标题、页脚、可读海报/地图/标牌文字全部不能出现在 CG 里。需要“有字”的地方用抽象图形或 UI 叠加。
2. **左区可承载文字**：36% 以左应是低细节、低亮度；如果最终左区偏亮，引擎遮罩会加厚，画面会变平，所以最好在 CG 阶段就控制。
3. **HERO 明确**：窗/城市地标/基地轴线落在 36–76% × 8–90%，不被常驻 UI 挡住。
4. **21:9 母版**：5120×2160；左右翼区是新增内容，不是拉伸；16:9/16:10 从中央裁切。
5. **分层**：建筑、道具、植被、远景、雾/体积光、实用光源至少可独立重渲；最终给合成 PNG/EXR。
6. **可编辑**：`.blend`、集合命名、材质、相机、色彩管理、渲染层都要能复现；不接受只有一张图。
7. **构图重做**：不要复刻概念图的大扇窗+藤蔓+桌面+电台组合；按 C 方案的 O3/O5 重新设计窗型、房间功能、机位与道具。
8. **地点名待定**：E-07/高架/列车未获叙事批准前，页脚不得写成既定正史；可在原型里保留为讨论用标签。
