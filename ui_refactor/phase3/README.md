## 3. 深度验收条款（v1）

以下条款针对现有 3 个试点界面，不新增页面。每条都必须绑定证据，而不是只写结论。

### 条款 0｜证据元数据（前置）
任何截图、测试、性能数字必须附带：commit hash、Godot 版本、seed、分辨率、DPI、场景状态、生成命令。
**验收**：随机抽 3 份证据，第三人按命令可复现；做不到即无效。

### 条款 1｜自动视觉回归
覆盖 12 个状态 × 1280×720 / 1920×1080 / 1920×1200 / 2560×1080。
**方法**：离屏捕获 + golden baseline + 感知 diff（SSIM 或差异像素比例，文字抗锯齿区域单独阈值）。
**验收**：无未解释的超阈值差异；基线随 commit 更新；单命令可跑。
**现状**：只有人工检查的 47 张截图，没有自动 diff。

### 条款 2｜真实玩家测试
5–8 名未参与设计者，执行“主菜单 → 单人/联机 → 战斗读状态 → 开关背包 → 返回”。
**证据**：完整录屏、时间戳操作日志、观察记录。
**验收**：≥80% 无需帮助完成；3 秒曝光后 ≥80% 正确说出生命/弹药/目标；无关键误读。
**现状**：未做。

### 条款 3｜输入与显示矩阵
键盘-only、鼠标、真实手柄分别完成全部 6 个菜单入口与核心战斗操作；125%/150% DPI；1280×720 至 2560×1080。
**验收**：焦点始终可见；10 次开关覆盖层后无卡键/焦点丢失；按下到视觉反馈 ≤2 帧；无裁切与重叠。
**现状**：键盘/鼠标有自动化测试；手柄未测试，不得声明支持；高 DPI 未验证。

### 条款 4｜性能预算
固定 seed、4 人尸潮最坏场景。
**证据**：Tracy/Godot Profiler trace、帧时间数组、RenderDoc GPU 捕获。
**验收**：UI CPU ≤2 ms p95、≤4 ms p99（1280×720）；整帧 ≤16.7 ms p99（最低规格机）；菜单隐藏后零 `_process`/零重绘；新旧版同场景对比。
**现状**：只有自定义平均帧时间，`_perf_ui.gd` 已删除，不可复现。

### 条款 5｜可读性与无障碍实证
在明、暗、雾、爆炸、低血量等真实背景下采样文字背后像素。
**验收**：正文 ≥4.5:1，大字/关键图形 ≥3:1；零“仅靠颜色”编码；减少动效开启后全部功能通过；无 >3 Hz 闪烁；色觉模拟下状态仍可区分。
**现状**：token 对比度已算；实际像素采样未做。`AMBER_DIM` 在面板上 3.86:1，低于正文目标。

### 条款 6｜网络真实性
150 ms RTT + 2% 丢包 + 30 ms 抖动，持续 5 分钟，双端同时记录。
**验收**：UI 状态与服务端偏差 ≤1 s；联机暂停不停止服务器 tick；断线/主机退出 ≤2 s 内可见；无卡死遮罩；抓包与双端日志归档。
**现状**：仅 localhost 通过；无延迟/丢包注入。

### 条款 7｜资产来源与许可
每个随包资产登记来源、许可、是否 AI/概念、目标分辨率。
**验收**：E-07 背景在 2560×1080 下有明确策略；字体可分发；Abandoned_House 授权确认；替换资产不需要改 UI。
**现状**：E-07 是 1672×941 webp 概念图（2560×1080 需 1.53× 放大）；Abandoned_House 授权不明。
