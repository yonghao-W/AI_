# 玩家可用性测试工具包

> 状态：**未执行**。需要 5–8 名真实玩家/硬件与录屏，不能由开发者自测替代。

## 目标

验证主菜单、单人/联机流程、战斗 HUD 与覆盖层是否能在无口头提示的情况下完成；比较新旧 UI 的首次操作时间、误操作与状态识别。

## 参与者

- 5–8 名，未参与本次设计；尽量覆盖不同 FPS/手柄经验与不同显示器。
- 记录：年龄区间（可选）、FPS 经验、键鼠/手柄、屏幕分辨率与缩放、是否色觉差异。
- 知情同意与录屏许可；不采集与测试无关的个人信息。

## 任务脚本（主持人只读，不提示）

1. **进入单人**：从主菜单进入单人行动，使用默认名称/种子；开始后 3 秒内观察 HUD，然后回答：当前生命、弹药、当前目标分别是什么？
2. **状态识别**：在低生命/换弹/空手（空仓）状态下，说出 HUD 正在表达什么；不得只靠颜色判断。
3. **覆盖层**：打开背包，确认当前装备，关闭并继续移动；再打开情报，关闭。
4. **暂停/恢复**：暂停，阅读提示，恢复；确认准星与输入恢复。
5. **联机**：创建房间；第二台客户端加入；双方准备并开始；观察队友倒地/断线提示；暂停并说明服务器是否仍在运行。
6. **返回**：回到主菜单，确认没有残留遮罩/卡死输入。

## 记录指标

| 指标 | 定义 |
|---|---|
| 任务完成 | 无帮助完成 / 需提示 / 失败 |
| 首次操作时间 | 任务开始到第一次有效点击/按键 |
| 误操作 | 点错、开错界面、重复按键、无法关闭 |
| 求助次数 | 主持人必须介入的次数 |
| 状态回忆 | 3 秒曝光后正确说出生命/弹药/目标 |
| 识别错误 | 把危险看成安全、把搬运看成可开火等 |
| 主观负荷 | NASA-TLX（可选）或 1–7  Likert |
| 新旧比较 | 盲测顺序随机；只作参考，不宣称统计显著性 |

## 初始通过标准（待基线校准）

- ≥80% 参与者无需帮助完成核心流程。
- ≥80% 在 3 秒曝光后正确说出生命/弹药/目标。
- 无关键误读（例如把“核心搬运中 · 无法开火”理解为可射击）。
- 覆盖层开关 5 次后无卡键/焦点丢失。
- 允许失败项；失败比“看起来更好”更有价值。
